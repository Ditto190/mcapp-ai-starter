## Summary

Added the full KM domain model to `knowledge-platform/schema.prisma`, replacing the Wasp default scaffold models. All 6 models from Task 1.1 are present in the Wasp schema file.

## Details

Wasp 0.23.0 scaffolds a default `schema.prisma` containing `User`, `Task`, and `Tag` starter models. These were replaced with the 6 KM models designed in Task 1.1:

- KnowledgeItem (central model, dual-track)
- Tag (KM domain tag)
- KnowledgeItemTag (explicit join table)
- MeetingNote (Track B source)
- Artifact (Track B output)
- InboxItem (staging area)

The datasource and generator blocks were preserved as-is (PostgreSQL + prisma-client-js).

## Output

- `knowledge-platform/schema.prisma` — 6 KM models, PostgreSQL datasource, ~110 lines

## Validation

File confirmed present with all 6 models. No Wasp default User/Task/Tag models remain.

## Issues

None for Phase 1 scope.

## Compatibility Concerns

**Wasp default User model removed:** Wasp's built-in authentication system requires a `User` model in `schema.prisma`. By replacing the default scaffold with KM-only models, the app cannot use Wasp auth (`app.auth {}`) without re-adding a `User` model first. This is intentional for Phase 1 (no auth required), but must be addressed before adding user authentication in Phase 2+. When adding auth: re-add Wasp-compatible `User` model and merge with KM schema, following Wasp 0.23.0 auth documentation.
