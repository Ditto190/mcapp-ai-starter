## Summary

Designed and created the Prisma schema for the foam-modme Knowledge Management Platform. Six models created covering the full two-track classification system.

## Details

Created `knowledge-platform/schema.prisma` with:

- PostgreSQL datasource bound to `DATABASE_URL` env var
- `prisma-client-js` generator
- 6 models: `KnowledgeItem`, `Tag`, `KnowledgeItemTag` (join), `MeetingNote`, `Artifact`, `InboxItem`

KnowledgeItem is the central model. It supports both tracks via: `track` (capability | task-bundle), `status` (raw | processed | deliverable), `capabilityPhase` (Track A), `domain` + `artifactType` (Track B). All string fields using constrained vocabulary are stored as `String` per design decision — Prisma enums avoided in favour of TypeScript-side Zod validation.

MeetingNote has a 1-to-many relationship to Artifact. InboxItem is a staging table for raw imports before classification. Tag uses an explicit join table (KnowledgeItemTag) to support cascade deletes cleanly.
